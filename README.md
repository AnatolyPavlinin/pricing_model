# Модель ценообразования (BA3)

Дипломный проект: алгоритм прогнозирования цен на основе исторических данных, количества продаж, затрат на продвижение и цен конкурентов.

## Требования

- Язык: Python не ниже 3.11
- Зависимости: Poetry
- БД: SQLite3
- Покрытие тестами: ≥75%
- Документация: README
- Формат входных данных: CSV

## Установка

1. Установи Poetry (если нет):
   ```
   curl -sSL https://install.python-poetry.org | python3 -
   
2. Инициализируй проект (если создаёшь с нуля):
    ```
    poetry init
    poetry config virtualenvs.in-project true
   
3. Установи зависимости:
    ```
   poetry install

## Настройка

1. Создай файл .env в корне проекта и укажи строку подключения к SQLite:
    ```
    DATABASE_URL=sqlite:///pricing.db

2. Положи файл csv_data.csv в папку data/.

## Запуск
    
    poetry run python main.py

При запуске программа запросит коэффициенты:

 - сезонный — отражает сезонность спроса (например, 1.2 в высокий сезон);
 - конкурентный — отражает позицию относительно конкурентов (1.0 = нейтрально, меньше 1 — конкуренты дешевле);
 - минимальный порог — доля от базовой цены, ниже которой прогноз не опускается (по умолчанию 0.9).

Результат: файл predictions.csv с прогнозом цен.

## Docker

### Сборка и запуск через Docker Compose

    docker compose up --build

Результат работы пайплайна (файл predictions.csv) появится в папке output/ на хосте.
Переменные окружения
Коэффициенты прогноза можно задать через переменные окружения (без интерактивного ввода):
   
   | Переменная                    | Описание                                          | По умолчанию |
   |-------------------------------|---------------------------------------------------|--------------|
   | INPUT_СЕЗОННЫЙ_КОЭФФИЦИЕНТ    | Сезонный коэффициент (1.2 — высокий сезон)        | 1.0          |
   | INPUT_КОЭФФИЦИЕНТ_КОНКУРЕНЦИИ | Коэффициент конкуренции (<1 — конкуренты дешевле) | 1.0          |
   | INPUT_МИНИМАЛЬНЫЙ_ПОРОГ_ЦЕНЫ  | Минимальная доля от базовой цены                  | 0.9          |
   
Пример запуска с кастомными коэффициентами:
   ```
   INPUT_СЕЗОННЫЙ_КОЭФФИЦИЕНТ=1.2 INPUT_КОЭФФИЦИЕНТ_КОНКУРЕНЦИИ=0.95 docker compose up --build
   ```
Струкция монтирования

| Путь на хосте	 | Путь в контейнере	 | Назначение         |
|----------------|--------------------|--------------------|
| ./data	        | /app/data	         | Входные CSV-файлы  |
| ./output	      | /app/output	       | Результат прогноза |

Ручная сборка без Compose
   ```
   docker build -t pricing-model .
   docker run -v $(pwd)/data:/app/data -v $(pwd)/output:/app/output pricing-model
   ```

## Алгоритм
1. **Базовая цена** — средняя цена по продукту за период.
2. **Прогноз** рассчитывается по формуле:

   `прогноз = базовая цена × сезонный коэффициент × коэффициент конкуренции + затраты на продвижение`

   - `сезонный коэффициент` — >1 в высокий сезон, <1 в низкий (по умолчанию 1.0).
   - `коэффициент конкуренции` — <1 если конкуренты демпингуют, >1 если продукту нет альтернативы (по умолчанию 1.0).
   - `затраты на продвижение` — наценка за маркетинговые активности (add_cost из данных).

3. **Ограничение**: прогноз не ниже 90% от базовой цены — защита от демпинга, который съедает маржу.
4. Коэффициенты задаются интерактивно при запуске или через переменные окружения (для Docker).

## Регулярное обновление

Для регулярного обновления пайплайн запускается по расписанию. Варианты:

- **Локально** — через cron или Task Scheduler: скрипт `main.py` загружает свежий CSV, сохраняет в БД и пересчитывает прогноз.
- **В Docker** — через `docker compose up` по расписанию (cron на хосте).
- **В CI/CD** — GitHub Actions с триггером `schedule` (cron-синтаксис), результат артефакт сохраняется.

Скрипт идемпотентен: повторный запуск с теми же данными не дублирует записи, а обновляет прогноз. 
Результат каждый раз перезаписывается в `output/predictions.csv`.
